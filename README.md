# 人际关系图谱 · EdgeEver 插件

把 EdgeEver 里的「人际关系」笔记本变成一张可交互的关系图谱：记录人物、关系强度与互动历史，
并可选地用密码把整份数据加密保存。

---

## 一、安装

EdgeEver 官方支持三种安装途径：已验证插件市场、公开 GitHub 仓库、Manifest 地址。
本插件走后两种即可（第三种需要你自己托管静态文件并配置 CORS）。

### 方式 A：从公开 GitHub 仓库安装（推荐）

1. 打开 EdgeEver → **插件市场**页面
2. 粘贴**仓库地址**（不是 Release 地址）：

   ```text
   https://github.com/zwjdujin/edgeever-rjgx
   ```

3. 会显示「未经验证的来源」——自由安装的正常提示，官方市场收录才有「已验证」标记
4. **首次启用社区客户端插件会弹一次信任确认**，确认后不再重复

EdgeEver 会读取默认分支根目录的 `manifest.json`，找到同版本号的 Release，
并行下载 `manifest.json` / `main.js` / `styles.css`，校验 SHA-256 后缓存到本机。

> **仓库硬性要求**：必须是公开仓库；`manifest.json` 必须在默认分支根目录；
> Release Tag 用 `1.0.0` 或 `v1.0.0`；Release 里的 `manifest.json` 必须与默认分支中的
> **完全一致**，否则安装会被拒绝。完整发布清单见 [RELEASE.md](./RELEASE.md)。

### 方式 B：从 Manifest 地址安装

自行用任意静态服务器托管 `manifest.json`、`main.js`、`styles.css`（三者同级），
并让响应带上允许 EdgeEver 来源访问的 **CORS 头**（`Access-Control-Allow-Origin`），
然后在插件市场页面粘贴 `manifest.json` 的完整 URL。相对 `entry` 地址基于 Manifest 地址解析。

### 方式 C：本地源码构建

```sh
npm install
npm run release    # 构建 + 组装 release/ 目录，并打印 SHA-256
npm run verify     # 类型检查 + 两套测试 + 构建 + 预览，一条命令全跑
```

`main.js` 与 `styles.css` 为构建产物，请勿直接修改。

## 二、首次使用

1. 打开命令面板，运行 **「人际关系图谱：打开面板」**
2. 插件会引导你创建名为 **「人际关系」** 的笔记本
3. 选择这一笔记本是否需要密码保护：

| 模式 | 数据形态 | 能全文搜索 | AI / MCP 可读 | 原生界面可见 |
|------|----------|-----------|--------------|-------------|
| **明文模式**（不设密码） | 每个人物一篇标准 Markdown 笔记 | 是 | 是 | 是，直接可读 |
| **加密模式**（设置密码） | 整份数据加密为单篇笔记的密文 | 否 | 否 | 只有乱码 |

4. 之后可以在面板右上角的 **「安全设置」** 里随时开启或关闭加密、修改密码

---

## 三、关于「密码保护」，必须先说清楚一件事

**EdgeEver 的插件 API 无法拦截宿主的原生界面。** 插件不能阻止你从左侧笔记本树直接点开某个笔记本，
也没有任何 API 可以给笔记本挂一把锁。这是平台的边界，不是实现偷懒。

所以本插件选择了唯一真正有效的做法：**加密数据本身，而不是给笔记本加锁。**

- 设了密码 → 人物数据以 AES-GCM 密文保存在单篇笔记里。即使从原生界面点进去，看到的也只是
  base64 乱码；没有密码，任何工具（包括 AI）都读不出内容。
- 没设密码 → 数据就是普通 Markdown 笔记，享受全部原生能力（搜索、同步、导出、MCP）。

**代价（请务必知悉）**：加密模式牺牲了「可搜索」和「AI 可读」。这是必然的取舍，不是可以两全的。
如果你希望 AI 能帮你分析人际关系，就应该用明文模式，转而依靠「谁能登录你的实例」来保护数据。

**密码无法找回。** 插件不保存密码，只保存 PBKDF2 的盐与一个校验块；密钥每次由你输入的密码现场派生，
只存在于内存中。密码遗失 = 数据无法恢复。

## 四、数据格式约定

明文模式下，每个人物是一篇独立笔记，格式如下（这是插件的解析契约）：

```markdown
# 蔡娇军

#人物/同事

## 基本

关系类型：同事
重要度：6
认识于：2019-03
备注：同项目组

## 人际关系

- 杜缙 | 同事 | 5 | 长期协作
- 赵志春 | 同事 | 3

## 互动记录

- 2026-09-11 | 线下 | 项目评审会
- 2026-08-28 | 微信 | 排期确认
```

解析器刻意做得宽容，手改笔记不容易写坏：

- 中文冒号 `：` 与英文冒号 `:` 都接受
- 强度既认数字 `1–5`，也认中文 `强 / 较强 / 中 / 较弱 / 弱`
- 列表符号 `-` 与 `*` 都接受
- 小节标题支持模糊匹配（如 `## 基本` / `## 资料` 都能识别）

**关系是双向写入的**：给 A 添加「B · 同事」时，B 的笔记里也会同步出现「A · 同事」。

|------|------|

## 六、代码结构

```
src/
├── index.ts        插件入口：注册面板与命令
├── types.ts        数据模型 + 宿主 API 的最小类型声明
├── crypto.ts       PBKDF2-SHA256 派生 + AES-GCM 加解密
├── markdown.ts     笔记 ↔ 数据的序列化与解析（格式契约在这里）
├── store.ts        明文 / 加密双模式存储、笔记本查找、模式迁移
├── graph.ts        零依赖力导向图 + Mermaid 导出
└── ui/
    ├── styles.ts   面板样式（构建时同时产出 styles.css）
    └── panel.ts    面板状态机：初始化引导 / 锁屏 / 主界面
```

`main.js` 与 `styles.css` 是构建产物，请勿直接修改。

## 七、已知限制

- **面板无法固定到主导航或编辑器侧栏**（平台 P0 限制），只能从插件菜单打开
- **插件只安装在当前设备**，不参与同步；数据靠笔记本身同步，不受影响
- **解锁状态**在本次运行内有效，关闭应用后需重新输入密码（面板提供「立即锁定」按钮）
- **加密模式不支持协作编辑**：数据集中在单篇笔记，多人同时改会互相覆盖
- 插件不读取 `Repository` / IndexedDB 等宿主内部结构，所有读写都走公开 API

---

## 八、安全说明

- `permissions` 字段在 EdgeEver 中只是**描述性元数据**，不是授权也不是沙箱。
  社区插件本质是同页面受信任代码，安装即等于完全信任。
- 加密采用 PBKDF2-SHA256（150,000 次迭代）派生 256 位密钥 + AES-GCM 认证加密。
- 盐与校验块以明文保存在数据笔记中（PBKDF2 本就设计成盐可公开），因此换设备后
  用同一个密码依然可以解锁，不依赖不同步的 Secret Storage。

```sh
# 2. 构建并组装资产

# 3. 把 manifest.json / main.js / styles.css 提交到默认分支
# 4. 新建 Release，Tag 用新版本号，上传 release/ 里的三个文件
```
